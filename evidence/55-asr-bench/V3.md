# V3 — Grid and context behavior

Date: 2026-10-20

`grid_settings()` produces 12 settings per model: beam sizes 1 and 5; hotwords off and on; context off, reference, and decoded; compute type int8. The reference mode is explicitly labelled as an upper bound in reports. The decoded mode uses formatted output from earlier clips.

`recording_groups()` sorts clips by source timestamps or utterance sequence and keeps different source recordings separate. `build_prompt()` accepts at most the three preceding clips, rejects a target clip or a clip from another recording, and selects reference or decoded text by mode. Context resets at each recording boundary. The public grid recorded zero `own_reference_in_prompt` rows across all 4,320 WER rows.

The benchmark sets `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1`, and `CUDA_VISIBLE_DEVICES=""`. It resolves model weights locally. Temporary model, beam, hotword, and prompt values are passed to `Decoder.transcribe`; they do not update the saved configuration or production defaults. The JSONL rows persist scores, clip IDs, settings, timings, and statuses, not hypothesis text.

The full grid used six cached models. The seven cached aliases, including the omitted large-v3 model, are listed in V1.
