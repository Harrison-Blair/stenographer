(sha256 `eb6c4360…5da7`) and `--no-cache-dir`. No audio and no transcript text

### Earlier attempts (not pinned)

1. Unlocked attempt 1: the converter failed with
   `ModuleNotFoundError: No module named 'onnx_ir'`. onnxruntime 1.31.0
   `MatMulNBitsQuantizer` imports `onnx_ir` without declaring it. Fix: pin
   `onnx-ir==1.1.0` (manager approved). The manifest `packages` block has six
   keys, which deviates from the spec's five, for this reason.
2. Unlocked attempt 2: exit 4. Two causes, both fixed. (a) A converter bug: the
   PyTorch joiner reference indexed `[0]` and had shape (5, 1, 8198) against
   (1, 5, 1, 8198). (b) The int8 max-abs rule (0.1) is wrong for this graph: the
   int8 encoder (accuracy_level 4, int8 activations) has a max rel diff of 0.70
   on random input, while a per-frame metric shows it is close (rms rel 0.406,
   per-frame cosine min 0.850, mean 0.920).
3. Manager decision 4 then added the full lock. The two runs above are the
   locked runs.

### Graph check thresholds and why

- fp32: max rel diff ≤ 1e-3 (observed ≤ 6.7e-6; task 26 saw about 3e-5).
- int8: mean cosine along the feature axis ≥ 0.8 (encoder axis 1 of
  (N, 1024, T), decoder axis 1 of (N, 640, U), joiner last axis). Observed
  minimum 0.9204 (encoder). A broken graph or a wrong quantization gives a
  cosine near 0.
- Joiner token argmax agreement (token logits only, not the 5 TDT durations):
  fp32 1.0, int8 ≥ 0.8; observed 1.000 for both.

Task 26 validated the same int8 recipe on real speech. Task B decodes a real
clip with these files.

## Measurements

| measure | value |
|---|---|
| conversion wall time | about 31 s (30.75 s, 30.83 s) |
| conversion peak RSS | 10.2 GiB (10,761,208 kB max) |
| whole `model download --asr` wall time | 1 min 41 s (1:40.65) |
| whole download peak RSS | 10,728,596 kB |
| peak disk under `XDG_DATA_HOME` during the download | 7,422,359,945 B = 6.91 GiB |
| installed size | 653 MiB (ASR) + 636 KiB (VAD) |

The peak disk was larger than the spec's 6 GiB rule. The manager approved
raising the rule to 8 GiB. The code (`MIN_FREE_BYTES`), its test, the CLI and
Setup texts, and the spec Download and Limits sections changed. The Limits
section also records the 10.2 GiB RSS and the times; there is no RAM check
(task D documents the RAM need). `ASR_SIZE_TEXT` reads "about 1.6 GB download,
8 GiB free disk while it converts". The 1.6 GB is an estimate: the 1.25 GB
source (measured) plus the package wheels (not measured separately).
