  - id `python_venv`, warning level.
  - fix "Run `sudo apt install python3-venv`."
  - It uses the same probe as the download (`bark_download.venv_available`).
  - It is added to `collect`.
- `cli/doctor/report.py`: label "python3 venv".
- `cli/hub/app.py`: a one-line map from `python_venv` to the "models" page, so
  the new check has a Hub section like every other check id.
- Tests:
  - passes for a python that can make a venv (the test interpreter).
  - warns with the apt fix for a fake `python3` script that exits 1, as on
    Ubuntu without python3-venv.
  - is collected for Doctor.
- Setup: `cli/setup/workflow.py` `_guided_setup` uses
  `bark_download.is_model_cached(data_dir)` and
  `download_bark_pro(data_dir, on_step=console.write)`. The prompt text names
  the 1.6 GB download and the 8 GiB free disk. After the download it prints the
  attribution.
- Setup tests: the fixture patches `bark_download`. The guided tests record
  `cache:/data` and `download:/data` events. Against the HEAD `workflow.py`,
  13 guided tests failed.
