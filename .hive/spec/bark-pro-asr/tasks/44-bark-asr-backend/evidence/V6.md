## Incident and fix: XDG_DATA_HOME is not isolated

The root `tests/conftest.py` redirects XDG_CONFIG/STATE/CACHE/RUNTIME but not
`XDG_DATA_HOME`. The first green run of the new wizard test therefore created
`~/.local/share/stenographer/models/asr/bark-pro-int8/` (empty stub files and an
all-zero manifest) in the user's real data dir. All of `models/` there was born
at that run (2026-10-21 22:50:00, `stat %w`) and held only those stubs; it was
deleted. The pre-existing `stenographer` binary and `_internal/` were not
touched. Both data-dir tests now set `XDG_DATA_HOME` to `tmp_path`. Every later
run left the real dir with only `_internal` and `stenographer`. The conftest
gap itself is not fixed here: adding `XDG_DATA_HOME` there would make the
existing real-VAD unit test always skip. The manager decides.
