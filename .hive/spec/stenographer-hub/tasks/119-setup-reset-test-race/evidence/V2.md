# V2 — Deterministic slow-save race proof

A scratch harness monkeypatched `ConfigDocument.save()` to set a `threading.Event` when the reset save began, then block on a second event. It ran the old one-pause sequence and checked the expected defaults while the save remained blocked. The assertion failed: `audio.input_device` was still `test microphone`. The harness released the save in `finally` so the worker could finish.

Old-sequence command:

```sh
PYTHONPATH="src:/tmp" /home/penguin/source/stenographer/.venv/bin/pytest -q /tmp/test_setup_reset_old_race.py
```

Result: expected failure, `1 failed in 0.36s`; the assertion showed `test microphone` instead of the default `None`.

For the changed test, a temporary pytest plugin held `ConfigDocument.save()` at the same event gate. It released the gate only when the captured `setup` worker's `wait()` was called. The actual modified test passed with the save held until it awaited the worker:

```sh
SLOW_SAVE_RELEASE_ON_WORKER_WAIT=1 PYTHONPATH="src:/tmp" \
  /home/penguin/source/stenographer/.venv/bin/pytest -q -p slow_setup_save_plugin \
  tests/cli/hub/test_setup_doctor.py::test_setup_defaults_replace_config_and_preserve_a_backup
```

Result: `1 passed in 0.32s`. The temporary harness files were removed after the run.
