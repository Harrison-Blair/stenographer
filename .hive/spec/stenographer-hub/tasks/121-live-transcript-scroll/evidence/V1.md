# V1 — transcript scroll tests

The pilot tests use fake sessions. They do not access a microphone or real audio.

## Red run

I temporarily stubbed `TranscriptScroll.update_content` to update the inner
`Static` only and disabled its virtual-size follow watcher. I restored the
implementation before the green run.

```sh
PYTHONPATH=src .venv/bin/pytest -q \
  tests/cli/live/test_app.py::test_transcript_scrolls_and_keeps_follow_state_when_lines_arrive \
  tests/cli/hub/test_live_view.py::test_live_transcript_scrolls_in_mixed_and_split_views_and_follows_new_lines
```

Result: **2 failed**, as expected. The standalone test found `scroll_y=0` and
`max_scroll_y=29`; the hub test found `scroll_y=0` and `max_scroll_y=32`. Both
failed because a populated session did not start at the bottom.

## Green run

I restored the follow implementation and ran the same command. Result:
**2 passed in 2.05s**.

The tests also cover line and page keys, Home/End, mouse-wheel input, holding
the view during new lines and the hub's 0.1-second refresh, and following new
lines at the bottom in mixed and split views.
